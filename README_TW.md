# 藏品助手 0.2.0 — Windows 試作版

《三國冰河時代》淘寶電腦客戶端的本地藏品記錄、單屬性配裝與回收檢查助手。提供繁體／簡體中文；CPU 辨識，無需 API、付費服務或顯示卡。程式不保存截圖。

## 從 0.1.0 更新

1. 關閉舊版助手。
2. 解壓新版，將新版資料夾內的程式檔案覆蓋到舊程式資料夾。
3. **保留舊資料夾的 `data` 和 `.venv`**；新版壓縮包不包含這兩個資料夾，不會覆蓋你的持有庫或已安裝套件。
4. 直接執行 `START_TW.cmd`／`START_CN.cmd`。本次依賴版本未變，已成功安裝的環境不必重新安裝。
5. 到「設定」重新選取遊戲中央完整面板，先測「擷取一次」。

也可將新版放在新資料夾並重新安裝；需要沿用資料時，在兩個版本都關閉的狀態，把舊 `data` 複製到新資料夾。不要同時開兩個版本寫入同一個庫。

## 這一版修正

- 日常視窗預設 **470×640**、最小 430×600。四頁分工：即時判斷、用途配裝、持有庫、設定。
- 取消常駐左側空白清單；替換畫面的左右藏品改成上方選單切換。
- 核對／編輯移至獨立視窗。原名稱、品質、戰力都是次要欄位，可留空；類別與完整屬性仍需確認。
- 擷取前檢查助手自己及其已開啟視窗：助手重疊時先嘗試移到選區旁，仍重疊的助手視窗暫時隱藏，完成擷取後恢復。也可在設定關閉自動移位，此時重疊視窗直接暫時隱藏。
- 單次與自動辨識使用相同的遮擋處理。所有視窗操作在主執行緒執行，OCR 在背景處理。
- 解析以屬性面板與每列名稱／數值為主，缺少品質或名稱不再丟掉整件藏品。
- 缺欄位、沒有配對的數值、讀到助手介面、未找到面板等情況，會顯示具體原因。只有數字而無屬性名稱時不會猜測。
- 不完整的解析先保留在本次畫面，需人工核對後保存；不會因缺字持續污染持有庫。可在「設定 → 診斷／辨識文字」查看全部原因。

**暫時隱藏只處理助手自己的視窗。其他程式、通知或彈窗仍可能遮住遊戲。**尚未改用取得後方遊戲影像的指定視窗擷取 API，也不保證任意遮擋都能穿透。

## 第一次安裝

1. 安裝 **Python 3.12 或 3.11 的 Windows x64 版本**，勾選 `Add Python to PATH` 並保留 Tcl/Tk。下載：https://www.python.org/downloads/windows/
2. 解壓到可寫入位置，例如桌面，不要直接在壓縮包內啟動。
3. 執行 `SETUP.cmd`。中國網路下載慢時可用 `SETUP_CHINA.cmd`（清華 TUNA PyPI 鏡像）。首次安裝需下載依賴，安裝完可離線執行。
4. 執行 `START_TW.cmd` 或 `START_CN.cmd`；也可在設定切換語言。
5. 想看示範可開 `DEMO.cmd`，示範庫與正式庫分開。

這是 Python 桌面試作包，尚未封裝成免安裝 EXE。套件與 OCR 模型在 `.venv`，其占用遠大於文字資料庫，但不會因正常擷取而不斷增加。版本未加入大型語言模型。

## 開始使用

1. 在遊戲打開「單件詳情」「替換藏品」或「回收」上方預覽。
2. 助手「設定 → 選取／重選遊戲區域」，框選中央完整面板，包含類別、名稱及全部屬性。不要只框右側數值。
3. 回到「即時判斷」按「擷取一次」。助手會先處理自身遮擋；若重疊且有空位，助手可能自動移到選區旁。
4. 看到屬性後，按「核對／編輯本件」，確認類別、每項屬性、單位和是否完整。勾選核對後保存。
5. 確認畫面穩定後，可開啟「開始辨識」。相同畫面連續兩次 OCR 一致、文字清楚、欄位完整且屬性規則已知，才自動確認。其他資料顯示待核對，不直接作為可靠的配裝或替代依據。

選區目前從主螢幕選取；請先把遊戲放到主螢幕。**移動遊戲、縮放、切換橫豎屏後要重選區。**助手移動不會改變遊戲選區。

開啟核對、診斷或回收確認會停止自動監看，避免正在編輯的資料被新結果覆蓋；完成後再按開始。按停止時會等待目前 OCR 結束。助手有模態確認對話框時，會要求先完成對話框再擷取。

## 各頁怎麼看

### 即時判斷

上方切換本次藏品，顯示類別、固定編號與保留判斷。表格完整列出屬性、本件值、其他已核對同欄位藏品的最高值。點選一列，下面顯示排名、差距與比較編號；品質和戰力不參與單屬性排名。

名稱／品質／戰力讀不到時，可先核對完整屬性再保存。這些次要欄位仍可在編輯視窗補填，方便遊戲內對照。因次要資訊缺失而尚無法完整識別的資料，不會直接自動確認。

### 用途配裝

選一項屬性，依每個欄位列出最高值藏品。並列時優先沿用生效中者。無資料時明確標示；加成數值合計不代表遊戲實際效率提升。

### 持有庫

以「欄位類別＋固定編號」標示藏品。雙擊或按「查看／編輯」核對完整資料。Ctrl 多選可檢查整批回收後是否會失去各項最佳值。

回收建議只處理單一屬性專精用途；交易、鑑定材料、隱藏效果與特殊組合仍需自行確認。

### 設定

集中放置選區、置頂、自動收錄、語言、圖片匯入、持有庫匯入／匯出、屬性規則與診斷文字。新屬性先標為規則待核對，可設定「越高越好」「越低越好」。條件式效果與未揭示屬性不會自動理解。

## 回收後同步刪除

1. 回收預覽只辨識上方正在展示的一件，不把下方所有勾選圖示當成已讀完整屬性。
2. 先在遊戲完成回收。
3. 助手持有庫選取相符紀錄，按「回收後同步刪除」。
4. 核對每件的已回收件數；雙擊可修改，0 表示不刪。勾選確認後同步。
5. 整件刪除時移除物品及其屬性、重算所有排名並回收資料庫空間；部分回收則扣減件數。

本版仍需你確認回收成功與相符紀錄，尚未自動追蹤遊戲回收結果。開始刪除會暫停辨識、丟棄先前讀取結果，避免剛刪的紀錄又被舊畫面加回。

## 同名物品與資料

- 同名但屬性不同會分開。名稱不是唯一身分，繁簡會統一處理。
- 完全相同的可見資料視為一組；再次辨識不會增加件數。若持有多件，要自行核對「件數」。程式無法憑畫面分辨完全相同個體。
- 固定編號不重排、不因刪除重用。數值以十進位保存，固定數量和百分比不混用。
- 只有當前已收錄且已核對的同欄位藏品可作可靠替代者。首次收錄仍需逐件打開詳情，程式不會自動點擊或捲動。
- 生效狀態依讀到的比較左側、詳情「卸下」按鈕或人工核對更新；關閉監看期間的變動無法自動得知。

## 空間、分享與排錯

- 不保存任何截圖，包括模糊結果；畫面只在記憶體處理。診斷可看辨識文字與解析原因。
- 正式庫：`data/inventory.sqlite3`；示範庫：`data/demo.sqlite3`。
- 錯誤記錄：`data/errors.log`，最多兩份，每份約 256 KB。安裝錯誤：`setup.log`。
- 分享給朋友請傳乾淨壓縮包，不要傳自己的 `data`、`.venv` 或匯出庫。
- 匯入 JSON 會合併資料、先標待核對；之前的副本 `data/before-import.sqlite3` 可自行刪除。回收本身不建立長期歷史庫。
- 若 DLL 載入失敗，請依微軟說明安裝 Visual C++ 2015–2022 x64：https://aka.ms/vs/17/release/vc_redist.x64.exe
- 安裝問題提供 `setup.log`；辨識問題提供操作步驟、診斷文字或畫面；執行錯誤可提供 `data/errors.log`。

## 驗證與限制

附 34 項測試，涵蓋既有資料比較、刪除重算、繁簡、單位、六張畫面解析，以及缺少名稱／品質、部分屬性缺失、助手介面偵測與擷取請求取消。

另以 Linux 虛擬螢幕測試助手與其附屬視窗刻意遮擋遊戲的情境：自動移位、無移位而暫時隱藏、連續及單次擷取都驗證取得完整遊戲影像，且沒有保存截圖。也檢查繁簡介面與次要資訊留空的保存流程。

**Windows／淘寶客戶端的實際視窗恢復、DPI 與擷取仍需試用確認。**其他程式遮擋、遊戲版面大改、動態效果或太小的字仍可能影響辨識。橫屏全圖匯入預設裁中央；非中央面板截圖請先裁出面板再匯入。

```text
python -m unittest discover -s tests -v
```
