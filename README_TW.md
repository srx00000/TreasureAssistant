# 藏品助手 0.6.0 使用說明

本地 OCR 藏品記錄、單項／多用途配裝及回收檢查工具，支援繁體與簡體中文，不保存截圖。

## 安裝與更新

第一次使用請安裝 Python 3.11 或 3.12 Windows x64，保留 Tcl/Tk 並勾選加入 PATH。解壓程式後執行 `SETUP.cmd`；中國網路可用 `SETUP_CHINA.cmd`。完成後執行 `START_TW.cmd` 或 `START_CN.cmd`。`DEMO.cmd` 為獨立示範庫。尚未封裝成 EXE，首次安裝需下載套件，之後可離線執行。

更新時關閉舊版、覆蓋程式檔，**保留原本的 `data` 和 `.venv`**。本次無須重裝依賴；啟動自動補上資料結構與新類別，既有藏品、草稿、固定編號及設定保留。需要備份時先關閉程式，複製 `data/inventory.sqlite3`。

## 擷取與確認

1. 遊戲打開單件詳情、替換藏品或回收預覽。
2. 「設定 → 選取／重選遊戲區域」，框選中央完整面板，包含類別、名稱及全部屬性，不要只框數字。
3. 「即時判斷 → 擷取一次」，對照全部屬性、數值與單位，正確時按「確認本件」。此按鈕直接核對保存，不停止監看或另開確認窗。
4. 有錯字或缺漏時按「編輯／補正」。這時停止監看；修正後勾選已核對完整屬性並保存，需要時自行重新開始辨識。
5. 畫面穩定後可「開始辨識」。連續兩次一致、完整、信心足夠且屬性規則已知才自動確認；其他有效觀測存為待核對草稿，重啟仍在。

選區目前由主螢幕選取，遊戲移動、縮放或切換橫豎屏後須重選。擷取前助手會自動移位或暫時隱藏自己的重疊視窗；其他程式遮擋仍會影響辨識。圖片匯入須保持文字直立，橫屏全圖預設裁中央；面板不在中央時請先裁圖。

總覽只能辨識欄位，不會把圖示建立成完整藏品。首次收錄仍需逐件打開詳情，程式不自動點擊、捲動、換裝或回收。鑑定結果頁尚未支援，請開詳情或替換頁。

## 替換頁優先顯示右側

框選左右名稱、戰力、完整屬性與「替換藏品」標題。遊戲點選下方物品後，助手同時記錄左側生效品及右側候選，預設顯示右側。同一候選下手動查看左側會保留選取；右側換成另一件時再回到右側。無須先按穿戴。

其中一側類別已知時，可推定另一側為相同替換欄位；兩側皆未知或有衝突時須人工指定類別。只讀正在顯示的詳情，不讀尚未展開的圖示。已確認名稱可供日後辨識類別使用。

## 誤讀與疑似重複

名稱、欄位、戰力相同，品階／等級相容且詞條數值吻合、能唯一對應到已核對藏品時：

- 本次只是漏讀，會明示沿用既有完整資料；不以缺漏觀測覆蓋可信屬性。
- 詞條疑似錯字，會列為「疑似重複」，不自動確認。比對後可按「沿用既有」移除該草稿，並記住這次誤讀對應，不改屬性或件數。
- 不確定時按「編輯／補正」，可「載入既有資料供比對」，逐項對照遊戲後再保存。

數值、單位、已知效果不同或可能對應多件時，不強行合併；身分資訊缺漏也可能仍需人工核對。「沿用既有」只適用明示的疑似對應；既有資料被修改或刪除後，舊對應會失效。

持有庫「整理誤讀」會暫停監看，檢查舊自動草稿、標示疑似關係並收束同一對應的重複草稿，保留較完整觀測；不直接轉正、不覆蓋可信藏品，也不整理人工暫存或編輯中的草稿。舊版已確認的誤讀資料仍須自行編輯或刪除。

## 逐列補正詞條

編輯視窗上方指定擺放欄位、件數及生效狀態。表格下方有名稱、數值及單位：

1. 新增：選擇或輸入詞條名稱、填數值、選 `%` 或「固定數量」，按「新增詞條」。名稱可搜尋，未知屬性可手填。
2. 修改：單擊表格一列，修改下方欄位後按「更新選取」。
3. 刪除：選取一列或多列，按「刪除選取」。
4. 最後仍在編輯的單列內容會隨保存套用；不允許同名同單位詞條重複。

下方可補實際名稱、品階／品質、等級與戰力。等級為選填，僅明示的「等級／Lv」標籤可自動讀取，其他情況留空；不由顏色、戰力或鑑定分數推測。新屬性人工確認時預設越高越好，已有方向規則保留，需要時在「屬性規則」修改。

## 持有庫與數量

清單主要顯示「實際名稱＋固定編號」，另有品階／等級、判斷與件數；詳情保留組別及擺放欄位。未讀到名稱則以欄位名稱代替。品階是遊戲稀有／史詩／傳奇等品質標籤；未提供的獨立等級不猜測。

頂端常駐顯示：已確認持有件數／資料組數、待核對筆數（含疑似重複數）及目前篩選顯示筆數。待核對與疑似重複不計入已確認件數。完全相同的可見資料視為一組，件數須人工核對；重複擷取不增加件數。同名不同屬性仍分開，名稱不是唯一識別鍵。

單擊、雙擊或上下鍵連續查看內嵌詳情，不跳分頁或開視窗；「詳情」可收合，中間分隔線可拖曳。背景辨識保留選取及捲動位置，編輯完成留在持有庫。可依狀態及組別篩選。設定中的視窗置頂會記憶。

## 分組欄位與配裝

| 組別 | 擺放欄位 |
| --- | --- |
| 精美飾物 | 漢燈、偶人、美玉、面具、松石、金器 |
| 祭祀禮樂 | 青銅觥、青銅尊、青銅壺、博山爐、青銅簋、青銅鼎 |

自訂類別歸入「自訂」。用途配裝預設選「精美飾物」，可切換「祭祀禮樂」或自訂，組別會記憶。**尚未確認兩組能否同時生效，請分組分析**；只有自行確認後才選「全部組別（需確認同時生效）」。回收替代及屬性比較仍按真正擺放欄位分開。

「單項專精」每欄選出該屬性最佳值，固定數量與百分比分開，並列時優先沿用生效品。只使用已確認資料，不按品質或戰力決定。

「多用途加權 → 設定多用途」可加入木材產量、煤礦產量等百分比目標及權重。1:1 代表等權合計，偏重木材可用 2:1。每欄選出加權總分最高者，列出各項加成與生效狀態完整時的差額。百分比差額以 `pp`（百分點）表示。

例如同欄三件為木材 +20%、煤礦 +20%、兩者各 +12%，1:1 會選兩者各 +12%；2:1 選木材 +20%。分數只是比較用途，不是實際產量百分比；模型假定各欄獨立且加成可相加，不保證兩項平均或最低門檻。多用途不混加固定容量等數量，固定數量使用單項專精。目標及模式會記憶。

## 用途影響與倉庫取捨

持有庫選取一件，或按 Ctrl 多選一批已確認藏品，再按「用途影響」。此功能不停止監看、不修改資料：

- 假設移除所選的全部持有件數，逐欄列出每項詞條的移除前最佳、移除後最佳及損失。
- 已選用途時，同時列出目前配裝組別範圍的用途分數變化；多用途按目前權重計分。
- `—` 表示沒有可靠替代或效果方向未知，不能當成零損失。
- 視窗是開啟當下的快照，資料或目標改變後請重開。

保守判斷維持：同欄一件保留藏品須完整替代全部已知效果，才列為可回收候選；不同藏品各自較高不等於單件完整替代。「多用途保留」不保證必定是某組權重最佳解。**尚未設定倉庫容量、常用用途及可接受損失的自動取捨政策**，本版先呈現代價供自行決定。交易、材料、隱藏效果及組合用途仍需自行確認。

## 回收與刪除

遊戲回收預覽只讀上方一件詳情，不把勾選圖示全視為已收錄。先在遊戲完成回收，再於持有庫選相符紀錄按「回收同步」；核對已回收件數，雙擊可修改，0 表示不刪，確認後同步。部分回收扣件數，全部回收刪除物品及屬性，重算排名；仍需人工確認遊戲成功與物品身分。

「刪除紀錄」是獨立操作，可刪正式紀錄或草稿，只影響助手資料。刪除及回收會暫停辨識並丟棄舊排隊結果，避免舊畫面立即加回；重新辨識相同物品仍可收錄。一般刪除不重用編號，也不建立長期回收歷史庫。

## 清空、備份與空間

「設定 → 資料管理」提供：

| 操作 | 清除內容 | 確認文字 |
| --- | --- | --- |
| 清空持有庫與待核對資料 | 全部藏品、草稿及誤讀對應；保留設定與規則 | `CLEAR` |
| 重設資料庫（含設定） | 同上，並清除設定／自訂規則，恢復預設類別 | `RESET` |

兩種完整清空都重設編號，下次從 `#0001`／`D0001` 開始。取消或文字不符不清除；更新程式本身不清庫。操作清除 SQLite 資料並回收空間，保留資料庫結構。不影響遊戲，也不刪已有匯出檔或 `data/before-import.sqlite3`。重設後需重選區域；本次語言保留至關閉，下次依啟動腳本指定語言。

- 正式庫：`data/inventory.sqlite3`；示範庫：`data/demo.sqlite3`。
- 不保存截圖，畫面只在記憶體處理；草稿診斷文字每筆上限 12,000 字元。安裝套件及 OCR 模型占用通常大於文字資料庫。
- 匯出 JSON v3 含等級、正式紀錄及草稿，匯入相容 v1／v2／v3，先標待核對。誤讀對應及疑似既有編號是本機關係，不隨 JSON 轉移。匯入前副本為 `data/before-import.sqlite3`。
- 分享給朋友使用乾淨程式包，勿附自己的持有庫、`.venv` 或日誌。
- 執行錯誤：`data/errors.log`，最多兩份、各約 256 KB；安裝錯誤：`setup.log`。
- DLL 載入失敗可依微軟說明安裝 Visual C++ 2015–2022 x64：https://aka.ms/vs/17/release/vc_redist.x64.exe

## 驗證與限制

122 項單元及回歸測試通過，含舊庫升級、誤讀對應與失效、不同數值不合併、件數保留、分組配裝、等級匯入匯出及唯讀影響分析。繁簡介面已驗證逐列編輯、右側優先、內嵌檢視、持續監看一鍵確認、資料管理及 470×640／430×600 排版，另有實際 OCR 遮擋擷取檢查。

Windows／淘寶實機的 DPI、視窗恢復與前景行為仍需試用確認。OCR 可能讀錯小字、特殊字形或漏詞條，連續一致也不代表必然正確。條件效果及遊戲實際收益無法只靠 OCR 理解，重要資料仍請對照遊戲。詳見 [KNOWN_ISSUES.md](KNOWN_ISSUES.md) 與 [VALIDATION.md](VALIDATION.md)。

python -m unittest discover -s tests -v
