# 藏品助手 0.3.1 — Windows 試作版

《三國冰河時代》淘寶電腦客戶端的本地藏品記錄、單屬性配裝與回收檢查助手。提供繁體／簡體中文；CPU 辨識，無需 API、付費服務或顯示卡。程式不保存截圖。

## 從 0.1.0／0.2.0／0.3.0 更新

1. 關閉舊版助手。
2. 解壓新版，將新版資料夾內的程式檔案覆蓋到舊程式資料夾。
3. **保留舊資料夾的 `data` 和 `.venv`**；新版壓縮包不包含這兩個資料夾，不會覆蓋你的持有庫或已安裝套件。
4. 直接執行 `START_TW.cmd`／`START_CN.cmd`。本次依賴版本未變，已成功安裝的環境不必重新安裝。
5. 到「設定」重新選取遊戲中央完整面板，先測「擷取一次」。

也可將新版放在新資料夾並重新安裝；需要沿用資料時，在兩個版本都關閉的狀態，把舊 `data` 複製到新資料夾。不要同時開兩個版本寫入同一個庫。

## v0.3.1 修正

- 清空持有庫或重設資料庫時，一併重設正式紀錄與草稿的自動編號；下一筆從 `#0001`／`D0001` 開始。
- 一般刪除或回收同步仍接續編號，避免重用既有編號。
- 升級不會清空或重排現有資料；需要從頭建立時，更新後重新執行清空。

## v0.3.0 功能

- 固定以正常直立方向辨識遊戲文字，避免純數字被方向分類翻轉。
- 依文字列位置逐行配對屬性與數值；漏讀數值時會標示待核對，避免合併鄰近屬性。
- 加入倉庫詳情「展示藏品對比」邊界；背景的「藏品回收」按鈕不再誤判成回收預覽。
- 不完整、低信心或規則未知的結果保存為待核對草稿，重啟仍可找到；草稿不參與最佳配裝或可靠的回收替代判斷。
- 持有庫新增全部／待核對／已確認篩選與「刪除紀錄」；設定新增「資料管理」，可以清空持有庫或重設資料庫。
- 匯出格式升為 JSON v2，包含草稿及診斷文字；仍可匯入 v1。
- 保留 470×640 四分頁介面及擷取前自動移位／暫時隱藏重疊助手視窗的功能。

更新只新增草稿資料表，保留既有資料與設定；**舊版已存錯的屬性不會自動修正**，請核對／編輯或刪除後重新辨識。

**暫時隱藏只處理助手自己的視窗。其他程式、通知或彈窗仍可能遮住遊戲。**尚未改用取得後方遊戲影像的指定視窗擷取 API，也不保證任意遮擋都能穿透。

## 第一次安裝

1. 安裝 **Python 3.12 或 3.11 的 Windows x64 版本**，勾選 `Add Python to PATH` 並保留 Tcl/Tk。下載：https://www.python.org/downloads/windows/
2. 解壓到可寫入位置，例如桌面，不要直接在壓縮包內啟動。
3. 執行 `SETUP.cmd`。中國網路下載慢時可用 `SETUP_CHINA.cmd`（清華 TUNA PyPI 鏡像）。首次安裝需下載依賴，安裝完可離線執行。
4. 執行 `START_TW.cmd` 或 `START_CN.cmd`；也可在設定切換語言。
5. 想看示範可開 `DEMO.cmd`，示範庫與正式庫分開。

這是 Python 桌面試作包，尚未封裝成免安裝 EXE。套件與 OCR 模型在 `.venv`，其占用遠大於文字資料庫，但不會因正常擷取而不斷增加。版本未加入大型語言模型。

## 開始使用

1. 在遊戲打開「單件詳情」「替換藏品」或「回收」上方預覽。
2. 助手「設定 → 選取／重選遊戲區域」，框選中央完整面板，包含類別、名稱及全部屬性。不要只框右側數值。
3. 回到「即時判斷」按「擷取一次」。助手會先處理自身遮擋；若重疊且有空位，助手可能自動移到選區旁。
4. 看到屬性後，按「核對／編輯本件」，確認類別、每項屬性、單位和是否完整。勾選核對後保存。
5. 確認畫面穩定後，可開啟「開始辨識」。相同畫面連續兩次 OCR 一致、文字清楚、欄位完整且屬性規則已知，才自動確認。其他可識別的資料自動保存為待核對草稿，可在持有庫繼續核對。只有空白或未找到藏品的畫面不會建立草稿。

選區目前從主螢幕選取；請先把遊戲放到主螢幕。**移動遊戲、縮放、切換橫豎屏後要重選區。**助手移動不會改變遊戲選區。

開啟核對、診斷或回收確認會停止自動監看，避免正在編輯的資料被新結果覆蓋；完成後再按開始。按停止時會等待目前 OCR 結束。助手有模態確認對話框時，會要求先完成對話框再擷取。

## 各頁怎麼看

### 即時判斷

上方切換本次藏品，顯示類別、固定編號與保留判斷。表格完整列出屬性、本件值、其他已核對同欄位藏品的最高值。點選一列，下面顯示排名、差距與比較編號；品質和戰力不參與單屬性排名。

名稱／品質／戰力讀不到時，可先核對完整屬性再保存。這些次要欄位仍可在編輯視窗補填，方便遊戲內對照。因次要資訊缺失而尚無法完整識別的資料，不會直接自動確認。

### 用途配裝

選一項屬性，依每個欄位列出最高值藏品。並列時優先沿用生效中者。無資料時明確標示；加成數值合計不代表遊戲實際效率提升。

### 持有庫

以「欄位類別＋固定編號」標示藏品，例如「偶人 #0001」；待核對草稿使用「偶人 D0001」。可篩選全部、待核對或已確認紀錄。雙擊或按「查看／編輯」核對完整資料；確認全部屬性並儲存後，草稿會轉成正式紀錄。Ctrl 多選可檢查整批回收後是否會失去各項最佳值。

「刪除紀錄」可以刪除選取的正式紀錄與草稿，確認後立即重算；只影響助手資料，不操作遊戲，不要求先在遊戲回收。誤讀、重複或不想保留的資料可用此功能清理。重新開始辨識相同藏品時仍可再次收錄。

回收建議只處理單一屬性專精用途；交易、鑑定材料、隱藏效果與特殊組合仍需自行確認。

### 設定

集中放置選區、置頂、自動收錄、語言、圖片匯入、持有庫匯入／匯出、屬性規則、資料管理與診斷文字。新屬性先標為規則待核對，可設定「越高越好」「越低越好」。條件式效果與未揭示屬性不會自動理解。

## 回收後同步刪除

1. 回收預覽只辨識上方正在展示的一件，不把下方所有勾選圖示當成已讀完整屬性。
2. 先在遊戲完成回收。
3. 助手持有庫選取相符紀錄，按「回收同步」。
4. 核對每件的已回收件數；雙擊可修改，0 表示不刪。勾選確認後同步。
5. 整件刪除時移除物品及其屬性、重算所有排名並回收資料庫空間；部分回收則扣減件數。

本版仍需你確認回收成功與相符紀錄，尚未自動追蹤遊戲回收結果。開始刪除會暫停辨識、丟棄先前讀取結果，避免剛刪的紀錄又被舊畫面加回。

## 清空持有庫或重設資料庫

在「設定 → 資料管理」選擇：

| 操作 | 清除內容 | 確認文字 |
| --- | --- | --- |
| 清空持有庫與待核對資料 | 全部藏品與草稿，保留語言、選區、類別與屬性規則 | `CLEAR` |
| 重設資料庫（含設定） | 全部藏品、草稿、自訂類別、屬性規則與持久化設定，恢復預設值 | `RESET` |

兩種完整清空操作都會一併重設正式紀錄與草稿的編號。取消或輸入不符時，資料與編號都不變。操作會停止辨識並忽略先前排隊的結果；完成後需自行重新開始。重設後要重新選取遊戲區域；本次介面語言保留到程式關閉，下次啟動使用啟動腳本指定的語言。

刪除會清除 SQLite 內的資料並回收空間，保留可供程式運作的資料庫檔案與結構；不會影響遊戲，也不會自動保存刪除前副本。需要保留時請先匯出。已有的匯出檔或 `data/before-import.sqlite3` 不會一併刪除。

## 同名物品與資料

- 同名但屬性不同會分開。名稱不是唯一身分，繁簡會統一處理。
- 完全相同的可見資料視為一組；再次辨識不會增加件數。若持有多件，要自行核對「件數」。程式無法憑畫面分辨完全相同個體。
- 重複讀取草稿會去重；類別、戰力相同且屬性為唯一相容子集時，較完整讀取會補入同一草稿。不同數值或多個可能候選會分開待核對；不憑相同名稱硬合併。手動暫存內容保留至人工確認。
- 一般刪除與回收同步不重排或重用編號；完整清空／重設才會從 0001 重新編號。數值以十進位保存，固定數量和百分比不混用。
- 只有當前已收錄且已核對的同欄位藏品可作可靠替代者。首次收錄仍需逐件打開詳情，程式不會自動點擊或捲動。
- 生效狀態依讀到的比較左側、詳情「卸下」按鈕或人工核對更新；關閉監看期間的變動無法自動得知。

## 空間、分享與排錯

- 不保存任何截圖，包括模糊結果；畫面只在記憶體處理。診斷可看辨識文字與解析原因；每筆草稿的原始辨識文字最多保存 12,000 字元。沒有每件藏品的圖片目錄。
- 正式庫：`data/inventory.sqlite3`；示範庫：`data/demo.sqlite3`。
- 錯誤記錄：`data/errors.log`，最多兩份，每份約 256 KB。安裝錯誤：`setup.log`。
- 分享給朋友請傳乾淨壓縮包，不要傳自己的 `data`、`.venv` 或匯出庫。
- 匯出 JSON v2 包含正式紀錄、待核對草稿及其診斷文字；匯入相容 v1／v2。匯入資料會合併、先標待核對；之前的副本 `data/before-import.sqlite3` 可自行刪除。回收本身不建立長期歷史庫。
- 若 DLL 載入失敗，請依微軟說明安裝 Visual C++ 2015–2022 x64：https://aka.ms/vs/17/release/vc_redist.x64.exe
- 安裝問題提供 `setup.log`；辨識問題提供操作步驟、診斷文字或畫面；執行錯誤可提供 `data/errors.log`。

## 驗證與限制

附 65 項測試，涵蓋屬性比較、單位、繁簡、逐行解析、倉庫四項屬性、草稿重啟與去重、核對轉正、刪除與交易回滾、清空、重設及既有資料庫升級。實際 OCR 已檢查六張原始遊戲畫面與新增倉庫詳情；四項屬性讀取為 2.74%、9.88%、2.91%、9.99%。字形信心不足仍會要求核對。

另以 Linux 虛擬螢幕驗證草稿重啟、編輯轉正、刪除取消／確認、清空確認文字、設定保留／重設、匯入匯出及繁簡介面。刻意遮擋遊戲時，自動移位、暫時隱藏、連續及單次擷取皆取得完整影像，視窗恢復且未保存截圖。

**Windows／淘寶客戶端的實際視窗恢復、DPI 與擷取仍需試用確認。**其他程式遮擋、遊戲版面大改、動態效果或太小的字仍可能影響辨識。圖片匯入應保持文字直立，不會自動旋轉。橫屏全圖匯入預設裁中央；非中央面板截圖請先裁出面板再匯入。
