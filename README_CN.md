# 藏品助手 0.2.0 — Windows 试作版

《三国冰河时代》淘宝电脑客户端的本地藏品记录、单属性配装与回收检查助手。提供繁体／简体中文；CPU 辨识，无需 API、付费服务或显示卡。程式不保存截图。

## 从 0.1.0 更新

1. 关闭旧版助手。
2. 解压新版，将新版资料夹内的程式档案覆盖到旧程式资料夹。
3. **保留旧资料夹的 `data` 和 `.venv`**；新版压缩包不包含这两个资料夹，不会覆盖你的持有库或已安装套件。
4. 直接执行 `START_TW.cmd`／`START_CN.cmd`。本次依赖版本未变，已成功安装的环境不必重新安装。
5. 到「设置」重新选取游戏中央完整面板，先测「截取一次」。

也可将新版放在新资料夹并重新安装；需要沿用资料时，在两个版本都关闭的状态，把旧 `data` 复制到新资料夹。不要同时开两个版本写入同一个库。

## 这一版修正

- 日常窗口预设 **470×640**、最小 430×600。四页分工：即时判断、用途配装、持有库、设置。
- 取消常驻左侧空白清单；替换画面的左右藏品改成上方选单切换。
- 核对／编辑移至独立窗口。原名称、品质、战力都是次要栏位，可留空；类别与完整属性仍需确认。
- 截取前检查助手自己及其已开启窗口：助手重叠时先尝试移到选区旁，仍重叠的助手窗口暂时隐藏，完成截取后恢复。也可在设置关闭自动移位，此时重叠窗口直接暂时隐藏。
- 单次与自动辨识使用相同的遮挡处理。所有窗口操作在主执行绪执行，OCR 在背景处理。
- 解析以属性面板与每列名称／数值为主，缺少品质或名称不再丢掉整件藏品。
- 缺栏位、没有配对的数值、读到助手介面、未找到面板等情况，会显示具体原因。只有数字而无属性名称时不会猜测。
- 不完整的解析先保留在本次画面，需人工核对后保存；不会因缺字持续污染持有库。可在「设置 → 诊断／辨识文字」查看全部原因。

**暂时隐藏只处理助手自己的窗口。其他程式、通知或弹窗仍可能遮住游戏。**尚未改用取得后方游戏影像的指定窗口截取 API，也不保证任意遮挡都能穿透。

## 第一次安装

1. 安装 **Python 3.12 或 3.11 的 Windows x64 版本**，勾选 `Add Python to PATH` 并保留 Tcl/Tk。下载：https://www.python.org/downloads/windows/
2. 解压到可写入位置，例如桌面，不要直接在压缩包内启动。
3. 执行 `SETUP.cmd`。中国网路下载慢时可用 `SETUP_CHINA.cmd`（清华 TUNA PyPI 镜像）。首次安装需下载依赖，安装完可离线执行。
4. 执行 `START_TW.cmd` 或 `START_CN.cmd`；也可在设置切换语言。
5. 想看示范可开 `DEMO.cmd`，示范库与正式库分开。

这是 Python 桌面试作包，尚未封装成免安装 EXE。套件与 OCR 模型在 `.venv`，其占用远大于文字资料库，但不会因正常截取而不断增加。版本未加入大型语言模型。

## 开始使用

1. 在游戏打开「单件详情」「替换藏品」或「回收」上方预览。
2. 助手「设置 → 选取／重选游戏区域」，框选中央完整面板，包含类别、名称及全部属性。不要只框右侧数值。
3. 回到「即时判断」按「截取一次」。助手会先处理自身遮挡；若重叠且有空位，助手可能自动移到选区旁。
4. 看到属性后，按「核对／编辑本件」，确认类别、每项属性、单位和是否完整。勾选核对后保存。
5. 确认画面稳定后，可开启「开始辨识」。相同画面连续两次 OCR 一致、文字清楚、栏位完整且属性规则已知，才自动确认。其他资料显示待核对，不直接作为可靠的配装或替代依据。

选区目前从主萤幕选取；请先把游戏放到主萤幕。**移动游戏、缩放、切换横竖屏后要重选区。**助手移动不会改变游戏选区。

开启核对、诊断或回收确认会停止自动监看，避免正在编辑的资料被新结果覆盖；完成后再按开始。按停止时会等待目前 OCR 结束。助手有模态确认对话框时，会要求先完成对话框再截取。

## 各页怎么看

### 即时判断

上方切换本次藏品，显示类别、固定编号与保留判断。表格完整列出属性、本件值、其他已核对同栏位藏品的最高值。点选一列，下面显示排名、差距与比较编号；品质和战力不参与单属性排名。

名称／品质／战力读不到时，可先核对完整属性再保存。这些次要栏位仍可在编辑窗口补填，方便游戏内对照。因次要资讯缺失而尚无法完整识别的资料，不会直接自动确认。

### 用途配装

选一项属性，依每个栏位列出最高值藏品。并列时优先沿用生效中者。无资料时明确标示；加成数值合计不代表游戏实际效率提升。

### 持有库

以「栏位类别＋固定编号」标示藏品。双击或按「查看／编辑」核对完整资料。Ctrl 多选可检查整批回收后是否会失去各项最佳值。

回收建议只处理单一属性专精用途；交易、鉴定材料、隐藏效果与特殊组合仍需自行确认。

### 设置

集中放置选区、置顶、自动收录、语言、图片导入、持有库导入／导出、属性规则与诊断文字。新属性先标为规则待核对，可设置「越高越好」「越低越好」。条件式效果与未揭示属性不会自动理解。

## 回收后同步删除

1. 回收预览只辨识上方正在展示的一件，不把下方所有勾选图示当成已读完整属性。
2. 先在游戏完成回收。
3. 助手持有库选取相符纪录，按「回收后同步删除」。
4. 核对每件的已回收件数；双击可修改，0 表示不删。勾选确认后同步。
5. 整件删除时移除物品及其属性、重算所有排名并回收资料库空间；部分回收则扣减件数。

本版仍需你确认回收成功与相符纪录，尚未自动追踪游戏回收结果。开始删除会暂停辨识、丢弃先前读取结果，避免刚删的纪录又被旧画面加回。

## 同名物品与资料

- 同名但属性不同会分开。名称不是唯一身分，繁简会统一处理。
- 完全相同的可见资料视为一组；再次辨识不会增加件数。若持有多件，要自行核对「件数」。程式无法凭画面分辨完全相同个体。
- 固定编号不重排、不因删除重用。数值以十进位保存，固定数量和百分比不混用。
- 只有当前已收录且已核对的同栏位藏品可作可靠替代者。首次收录仍需逐件打开详情，程式不会自动点击或卷动。
- 生效状态依读到的比较左侧、详情「卸下」按钮或人工核对更新；关闭监看期间的变动无法自动得知。

## 空间、分享与排错

- 不保存任何截图，包括模糊结果；画面只在记忆体处理。诊断可看辨识文字与解析原因。
- 正式库：`data/inventory.sqlite3`；示范库：`data/demo.sqlite3`。
- 错误记录：`data/errors.log`，最多两份，每份约 256 KB。安装错误：`setup.log`。
- 分享给朋友请传干净压缩包，不要传自己的 `data`、`.venv` 或导出库。
- 导入 JSON 会合并资料、先标待核对；之前的副本 `data/before-import.sqlite3` 可自行删除。回收本身不建立长期历史库。
- 若 DLL 载入失败，请依微软说明安装 Visual C++ 2015–2022 x64：https://aka.ms/vs/17/release/vc_redist.x64.exe
- 安装问题提供 `setup.log`；辨识问题提供操作步骤、诊断文字或画面；执行错误可提供 `data/errors.log`。

## 验证与限制

附 34 项测试，涵盖既有资料比较、删除重算、繁简、单位、六张画面解析，以及缺少名称／品质、部分属性缺失、助手介面侦测与截取请求取消。

另以 Linux 虚拟萤幕测试助手与其附属窗口刻意遮挡游戏的情境：自动移位、无移位而暂时隐藏、连续及单次截取都验证取得完整游戏影像，且没有保存截图。也检查繁简介面与次要资讯留空的保存流程。

**Windows／淘宝客户端的实际窗口恢复、DPI 与截取仍需试用确认。**其他程式遮挡、游戏版面大改、动态效果或太小的字仍可能影响辨识。横屏全图导入预设裁中央；非中央面板截图请先裁出面板再导入。

```text
python -m unittest discover -s tests -v
```
