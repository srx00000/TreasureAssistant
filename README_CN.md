# 藏品助手 0.6.0 使用说明

本地 OCR 藏品记录、单项／多用途配装及回收检查工具，支援繁体与简体中文，不保存截图。

## 安装与更新

第一次使用请安装 Python 3.11 或 3.12 Windows x64，保留 Tcl/Tk 并勾选加入 PATH。解压程式后执行 `SETUP.cmd`；中国网路可用 `SETUP_CHINA.cmd`。完成后执行 `START_TW.cmd` 或 `START_CN.cmd`。`DEMO.cmd` 为独立示范库。尚未封装成 EXE，首次安装需下载套件，之后可离线执行。

更新时关闭旧版、覆盖程式档，**保留原本的 `data` 和 `.venv`**。本次无须重装依赖；启动自动补上资料结构与新类别，既有藏品、草稿、固定编号及设定保留。需要备份时先关闭程式，复制 `data/inventory.sqlite3`。

## 撷取与确认

1. 游戏打开单件详情、替换藏品或回收预览。
2. 「设定 → 选取／重选游戏区域」，框选中央完整面板，包含类别、名称及全部属性，不要只框数字。
3. 「即时判断 → 撷取一次」，对照全部属性、数值与单位，正确时按「确认本件」。此按钮直接核对保存，不停止监看或另开确认窗。
4. 有错字或缺漏时按「编辑／补正」。这时停止监看；修正后勾选已核对完整属性并保存，需要时自行重新开始辨识。
5. 画面稳定后可「开始辨识」。连续两次一致、完整、信心足够且属性规则已知才自动确认；其他有效观测存为待核对草稿，重启仍在。

选区目前由主萤幕选取，游戏移动、缩放或切换横竖屏后须重选。撷取前助手会自动移位或暂时隐藏自己的重叠视窗；其他程式遮挡仍会影响辨识。图片汇入须保持文字直立，横屏全图预设裁中央；面板不在中央时请先裁图。

总览只能辨识栏位，不会把图示建立成完整藏品。首次收录仍需逐件打开详情，程式不自动点击、卷动、换装或回收。鉴定结果页尚未支援，请开详情或替换页。

## 替换页优先显示右侧

框选左右名称、战力、完整属性与「替换藏品」标题。游戏点选下方物品后，助手同时记录左侧生效品及右侧候选，预设显示右侧。同一候选下手动查看左侧会保留选取；右侧换成另一件时再回到右侧。无须先按穿戴。

其中一侧类别已知时，可推定另一侧为相同替换栏位；两侧皆未知或有冲突时须人工指定类别。只读正在显示的详情，不读尚未展开的图示。已确认名称可供日后辨识类别使用。

## 误读与疑似重复

名称、栏位、战力相同，品阶／等级相容且词条数值吻合、能唯一对应到已核对藏品时：

- 本次只是漏读，会明示沿用既有完整资料；不以缺漏观测覆盖可信属性。
- 词条疑似错字，会列为「疑似重复」，不自动确认。比对后可按「沿用既有」移除该草稿，并记住这次误读对应，不改属性或件数。
- 不确定时按「编辑／补正」，可「载入既有资料供比对」，逐项对照游戏后再保存。

数值、单位、已知效果不同或可能对应多件时，不强行合并；身分资讯缺漏也可能仍需人工核对。「沿用既有」只适用明示的疑似对应；既有资料被修改或删除后，旧对应会失效。

持有库「整理误读」会暂停监看，检查旧自动草稿、标示疑似关系并收束同一对应的重复草稿，保留较完整观测；不直接转正、不覆盖可信藏品，也不整理人工暂存或编辑中的草稿。旧版已确认的误读资料仍须自行编辑或删除。

## 逐列补正词条

编辑视窗上方指定摆放栏位、件数及生效状态。表格下方有名称、数值及单位：

1. 新增：选择或输入词条名称、填数值、选 `%` 或「固定数量」，按「新增词条」。名称可搜寻，未知属性可手填。
2. 修改：单击表格一列，修改下方栏位后按「更新选取」。
3. 删除：选取一列或多列，按「删除选取」。
4. 最后仍在编辑的单列内容会随保存套用；不允许同名同单位词条重复。

下方可补实际名称、品阶／品质、等级与战力。等级为选填，仅明示的「等级／Lv」标签可自动读取，其他情况留空；不由颜色、战力或鉴定分数推测。新属性人工确认时预设越高越好，已有方向规则保留，需要时在「属性规则」修改。

## 持有库与数量

清单主要显示「实际名称＋固定编号」，另有品阶／等级、判断与件数；详情保留组别及摆放栏位。未读到名称则以栏位名称代替。品阶是游戏稀有／史诗／传奇等品质标签；未提供的独立等级不猜测。

顶端常驻显示：已确认持有件数／资料组数、待核对笔数（含疑似重复数）及目前筛选显示笔数。待核对与疑似重复不计入已确认件数。完全相同的可见资料视为一组，件数须人工核对；重复撷取不增加件数。同名不同属性仍分开，名称不是唯一识别键。

单击、双击或上下键连续查看内嵌详情，不跳分页或开视窗；「详情」可收合，中间分隔线可拖曳。背景辨识保留选取及卷动位置，编辑完成留在持有库。可依状态及组别筛选。设定中的视窗置顶会记忆。

## 分组栏位与配装

| 组别 | 摆放栏位 |
| --- | --- |
| 精美饰物 | 汉灯、偶人、美玉、面具、松石、金器 |
| 祭祀礼乐 | 青铜觥、青铜尊、青铜壶、博山炉、青铜簋、青铜鼎 |

自订类别归入「自订」。用途配装预设选「精美饰物」，可切换「祭祀礼乐」或自订，组别会记忆。**尚未确认两组能否同时生效，请分组分析**；只有自行确认后才选「全部组别（需确认同时生效）」。回收替代及属性比较仍按真正摆放栏位分开。

「单项专精」每栏选出该属性最佳值，固定数量与百分比分开，并列时优先沿用生效品。只使用已确认资料，不按品质或战力决定。

「多用途加权 → 设定多用途」可加入木材产量、煤矿产量等百分比目标及权重。1:1 代表等权合计，偏重木材可用 2:1。每栏选出加权总分最高者，列出各项加成与生效状态完整时的差额。百分比差额以 `pp`（百分点）表示。

例如同栏三件为木材 +20%、煤矿 +20%、两者各 +12%，1:1 会选两者各 +12%；2:1 选木材 +20%。分数只是比较用途，不是实际产量百分比；模型假定各栏独立且加成可相加，不保证两项平均或最低门槛。多用途不混加固定容量等数量，固定数量使用单项专精。目标及模式会记忆。

## 用途影响与仓库取舍

持有库选取一件，或按 Ctrl 多选一批已确认藏品，再按「用途影响」。此功能不停止监看、不修改资料：

- 假设移除所选的全部持有件数，逐栏列出每项词条的移除前最佳、移除后最佳及损失。
- 已选用途时，同时列出目前配装组别范围的用途分数变化；多用途按目前权重计分。
- `—` 表示没有可靠替代或效果方向未知，不能当成零损失。
- 视窗是开启当下的快照，资料或目标改变后请重开。

保守判断维持：同栏一件保留藏品须完整替代全部已知效果，才列为可回收候选；不同藏品各自较高不等於单件完整替代。「多用途保留」不保证必定是某组权重最佳解。**尚未设定仓库容量、常用用途及可接受损失的自动取舍政策**，本版先呈现代价供自行决定。交易、材料、隐藏效果及组合用途仍需自行确认。

## 回收与删除

游戏回收预览只读上方一件详情，不把勾选图示全视为已收录。先在游戏完成回收，再于持有库选相符纪录按「回收同步」；核对已回收件数，双击可修改，0 表示不删，确认后同步。部分回收扣件数，全部回收删除物品及属性，重算排名；仍需人工确认游戏成功与物品身分。

「删除纪录」是独立操作，可删正式纪录或草稿，只影响助手资料。删除及回收会暂停辨识并丢弃旧排队结果，避免旧画面立即加回；重新辨识相同物品仍可收录。一般删除不重用编号，也不建立长期回收历史库。

## 清空、备份与空间

「设定 → 资料管理」提供：

| 操作 | 清除内容 | 确认文字 |
| --- | --- | --- |
| 清空持有库与待核对资料 | 全部藏品、草稿及误读对应；保留设定与规则 | `CLEAR` |
| 重设资料库（含设定） | 同上，并清除设定／自订规则，恢复预设类别 | `RESET` |

两种完整清空都重设编号，下次从 `#0001`／`D0001` 开始。取消或文字不符不清除；更新程式本身不清库。操作清除 SQLite 资料并回收空间，保留资料库结构。不影响游戏，也不删已有汇出档或 `data/before-import.sqlite3`。重设后需重选区域；本次语言保留至关闭，下次依启动脚本指定语言。

- 正式库：`data/inventory.sqlite3`；示范库：`data/demo.sqlite3`。
- 不保存截图，画面只在记忆体处理；草稿诊断文字每笔上限 12,000 字元。安装套件及 OCR 模型占用通常大于文字资料库。
- 汇出 JSON v3 含等级、正式纪录及草稿，汇入相容 v1／v2／v3，先标待核对。误读对应及疑似既有编号是本机关系，不随 JSON 转移。汇入前副本为 `data/before-import.sqlite3`。
- 分享给朋友使用干净程式包，勿附自己的持有库、`.venv` 或日志。
- 执行错误：`data/errors.log`，最多两份、各约 256 KB；安装错误：`setup.log`。
- DLL 载入失败可依微软说明安装 Visual C++ 2015–2022 x64：https://aka.ms/vs/17/release/vc_redist.x64.exe

## 验证与限制

122 项单元及回归测试通过，含旧库升级、误读对应与失效、不同数值不合并、件数保留、分组配装、等级汇入汇出及唯读影响分析。繁简介面已验证逐列编辑、右侧优先、内嵌检视、持续监看一键确认、资料管理及 470×640／430×600 排版，另有实际 OCR 遮挡撷取检查。

Windows／淘宝实机的 DPI、视窗恢复与前景行为仍需试用确认。OCR 可能读错小字、特殊字形或漏词条，连续一致也不代表必然正确。条件效果及游戏实际收益无法只靠 OCR 理解，重要资料仍请对照游戏。详见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md) 与 [VALIDATION.md](VALIDATION.md)。
